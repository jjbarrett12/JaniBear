# Account Intelligence Profile — Architecture & Implementation

**Business goal:** One evolving AI intelligence profile per lead/account so JANIBEAR can prepare proposals, handoffs, activations, staffing recommendations, and route-aware assignment with minimal manual effort. Profile **begins at lead stage** and evolves through walkthrough, proposal, close, activation, and active service.

**Canonical lifecycle:** Hunt → Stalk → Kill → Launch to Ops.

**Critical rule:** The profile must exist from lead stage onward; it must not only exist after close.

## 1. Schema plan

### 1.1 Central profile (hybrid model)

**account_intelligence_profiles**

- **Identity / linkage:** `id`, `org_id`, `lead_id` (nullable FK → leads), `account_id` (nullable FK → accounts), `opportunity_id` (nullable FK → opportunities). Constraint: at least one of `lead_id` or `account_id` must be set.
- **Structured (operational/sales):**
  - Building: `building_type`, `square_footage_estimate`, `restroom_count`, `floor_count`
  - Scope: `cleaning_scope_summary` (text)
  - Service: `service_frequency`, `service_days` (jsonb), `service_window` (evening/day/mixed)
  - Labor: `estimated_labor_hours_per_visit`, `recommended_headcount`
  - Route: `recommended_cluster_id` (FK → route_clusters, nullable)
  - Readiness: `proposal_readiness` (text), `activation_readiness` (text)
  - Flags: `risk_flags` (jsonb array), `missing_data_flags` (jsonb array)
- **Verification:** `verification_state` enum: `ai_estimated` | `human_confirmed` | `contract_confirmed` | `inferred` | `stale`
- **JSON (flexible):** `raw_ai_output` (jsonb), `evidence_summary` (jsonb), `confidence_metadata` (jsonb), `extracted_data` (jsonb)
- **Audit:** `created_at`, `updated_at`, `last_event_at` (last time an event updated this profile)

### 1.2 Supporting tables

**profile_sources** — Evidence / provenance for profile data.

- `id`, `org_id`, `profile_id` (FK), `source_type` (e.g. `lead_created`, `walkthrough_completed`, `lidar_uploaded`, `proposal_generated`), `source_entity_type` (`lead` | `walkthrough` | `proposal` | `account` | `contract`), `source_entity_id` (uuid), `captured_at`, `meta` (jsonb).

**extracted_spaces** — AI-extracted zones/rooms/floors/areas (e.g. from LiDAR or scope).

- `id`, `org_id`, `profile_id` (FK), `name`, `space_type` (`zone` | `room` | `floor` | `area`), `sort_order`, `geo_json` (jsonb), `meta` (jsonb), `created_at`.

**ai_recommendations** — AI recommendations over time (proposal, staffing, route).

- `id`, `org_id`, `profile_id` (FK), `recommendation_type` (text), `content` (text or jsonb), `status` (`pending` | `accepted` | `dismissed`), `created_at`, `resolved_at`, `resolved_by` (uuid, nullable).

**ai_readiness_tasks** — Missing-data or readiness tasks generated by AI.

- `id`, `org_id`, `profile_id` (FK), `task_type` (`missing_data` | `proposal_readiness` | `activation_readiness`), `title`, `description` (text, nullable), `status` (`open` | `done` | `dismissed`), `due_at` (nullable), `created_at`, `resolved_at`, `meta` (jsonb).

### 1.3 Links to canonical entities

- **Lead:** `account_intelligence_profiles.lead_id` → leads.id. Profile can be created when lead is created (Hunt).
- **Walkthrough:** profile_sources with source_entity_type = 'walkthrough', source_entity_id = walkthrough.id; walkthrough data can merge into profile (Stalk).
- **Proposal:** profile_sources with source_entity_type = 'proposal'; proposal/bid id in source_entity_id (Kill).
- **Account:** `account_intelligence_profiles.account_id` → accounts.id. Set when lead converts or when profile is created for an existing account (Launch to Ops, active service).

No rename of existing site/location tables; profile is additive and references leads/accounts only.

## 2. Verification / confidence state

- **verification_state** on profile: overall state of the intelligence (ai_estimated → human_confirmed → contract_confirmed; or inferred; or stale when data is old).
- **confidence_metadata** (jsonb): optional field-level or section-level confidence and source (e.g. `{ "square_footage": { "value": 5000, "source": "lidar", "confidence": 0.9 } }`).

## 3. Event-driven update triggers

| Event | Trigger point | Action |
|-------|----------------|--------|
| lead_created | After insert into leads | Create or get profile for lead_id; set last_event_at. |
| walkthrough_scheduled | When walkthrough is scheduled | Attach source; optionally refresh profile from walkthrough. |
| lidar_uploaded | When LiDAR/walkthrough scan uploaded | Attach source; merge extracted_data / spaces; update building/scope. |
| photos_uploaded | When photos uploaded to walkthrough | Attach source; optional AI merge. |
| walkthrough_completed | When walkthrough marked complete | Attach source; merge scope, sqft, rooms; update verification. |
| proposal_generated | When proposal/bid created | Attach source; merge proposal readiness. |
| contract_uploaded | When contract doc uploaded | Attach source; set verification_state contract_confirmed where applicable. |
| deal_closed_won | When opportunity won | Set account_id on profile if not set; attach source. |
| launch_to_ops_requested | When launch packet sent to ops | Update activation_readiness; attach source. |
| ops_activation_started | When ops accepts / starts activation | Update profile; attach source. |
| account_activated | When account status → active | Update profile; attach source. |

Implementation: application-layer calls to a profile service (e.g. `upsertProfileForLead`, `attachSource`, `mergeFromWalkthrough`). DB triggers are optional (e.g. only to set `updated_at` / `last_event_at` on profile when a source is inserted).

## 4. Population / backfill strategy

- **New leads:** On lead create, call `ensureProfileForLead(orgId, leadId)` → create profile with lead_id, account_id null.
- **Existing leads without profile:** Backfill job or on-first-access: for each lead without a profile, create one (lead_id set, account_id from converted_account_id if any).
- **Accounts without profile:** When an account is created from conversion, ensure profile has account_id set; or create profile by account when first needed (e.g. first activation recommendation).
- **Merge from existing data:** When profile is created from lead, seed building_type, service_frequency_guess, address from leads table into structured + evidence_summary. Same for walkthrough/proposal when sources are attached.

## 6. QA plan

- Profile created when lead is created (lead_id set, account_id null).
- Profile can be looked up by lead_id and by account_id; after conversion, same profile has both.
- Attach source: profile_sources row created; last_event_at updated on profile.
- Extracted spaces: insert and list by profile_id.
- AI recommendations and readiness tasks: CRUD and filter by profile_id and status.
- Verification state: update and persist; confidence_metadata optional.
- RLS: org-scoped; only org members (or site admin) can read/write profiles and related tables.
- Backfill: existing leads get profiles without duplicating or overwriting account data.

---

## 7. Rollback

- New tables only; no changes to leads, accounts, walkthroughs, proposals. Drop new tables and remove call sites to revert.

- **Migration 127:** account_intelligence_profiles (lead_id, account_id, opportunity_id, structured fields, verification_state, raw_ai_output, evidence_summary, confidence_metadata, extracted_data, last_event_at), profile_sources, extracted_spaces, ai_recommendations, ai_readiness_tasks. **Population:** New leads get a profile on create. Existing leads get a profile on first ensureForLead (e.g. when opening lead detail or when converting). On conversion, profile is linked to account and opportunity.
